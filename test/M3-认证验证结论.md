# M3 身份认证验证结论

- 日期：2026-10-02
- 范围：CloudBase 身份认证的 **JWT 本地验签**（M3-1）
- 结论：**可行**。访问令牌为 **RS256 JWT**，存在**公开 JWKS 端点**；平台后端 / Agent 运行时均可离线验签，无需共享密钥、无需调用中转接口。

> **后续决策（2026-10-02）**：平台最终选择 **自建认证**（见 `docs/spec/技术架构规格.md` v0.2）。本文件作为 **CloudBase 认证的调研存档**保留。

## 一、验签方案（实测）

| 项 | 值 |
|---|---|
| OIDC 发现 | `https://<envId>.ap-shanghai.tcb-api.tencentcloudapi.com/.well-known/openid-configuration`（200） |
| issuer | `https://<envId>.ap-shanghai.tcb-api.tencentcloudapi.com` |
| **jwks_uri** | `https://<envId>.ap-shanghai.tcb-api.tencentcloudapi.com/auth/v1/certs` |
| 备用 JWKS（网关域） | `https://<envId>.api.tcloudbasegateway.com/auth/v1/certs`（200，同一套能力） |
| 算法 | **RS256**（`id_token_signing_alg_values_supported=["RS256"]`；JWKS `kty=RSA, use=sig`） |
| token_endpoint | `…/auth/v1/token`；userinfo `…/auth/v1/user/me`；device `…/auth/v1/device/code` |

**验签步骤（推荐）**：

1. 从 token header 取 `kid`、`alg`；
2. 拉 JWKS（`/auth/v1/certs`），按 `kid` 选公钥（缓存，按 `kid` 刷新）；
3. 校验 RS256 签名；
4. 校验 `aud == <envId>`、`exp`、以及 `iss`（**以实际 token 为准**，见下）；
5. `sub` 即用户 UID；`role` ∈ `anon/authenticated/service_role`。

> 实测：**AGS 沙盒内** `GET …/auth/v1/certs` 返回 **200**（验签公钥可被沙盒/托管服务获取）。

## 二、令牌结构（实测）

- Publishable Key 本身也是一个 RS256 JWT，payload 关键字段：
  `iss=https://<envId>.ap-shanghai.tcb-api.tencentcloudapi.com`、`aud=<envId>`、`sub="anon"`、`role="anon"`、`scope="anonymous"`、`meta.platform="PublishableKey"`。
- 用户 access_token 结构一致（文档：`sub`=用户 UID，`role`=authenticated 等）。

## 三、关键坑（必须遵守）

1. **JWKS 路径只有 `/auth/v1/certs`**：`/auth/v1/.well-known/jwks.json` = 404；`/.well-known/jwks.json` = 401。
2. **issuer 有两个域**：token 里是 `…ap-shanghai.tcb-api.tencentcloudapi.com`，而文档写 `…api.tcloudbasegateway.com/auth/v1`。**务必以实际 token 的 `iss` 为准**，或用对应域的 OIDC 发现；两域都能取 `/auth/v1/certs`。
3. **不要拿 Publishable Key 当 Bearer 令牌调用用户接口**：它的 `kid`（`5af1590d-…`）**不在**用户 JWKS 中，服务端会报
   `Unable to find a signing key that matches '5af1590d-…'`。
4. **认证 API 机制**（实测）：
   - 请求头需要 **`apikey: <Publishable Key>`**；
   - 登录：`POST /auth/v1/signin`（username/password 或 verification_token）；
   - 匿名：`POST /auth/v1/signin/anonymously`（需 **`x-device-id`** 头，16–48 字符）；
   - 短信/邮箱：`/auth/v1/signup`（要求 phone/email）；
   - `POST /auth/v1/token` 仅支持 OAuth 授权类型（authorization_code / refresh_token / client_credentials / device_code），**无 password grant**。
5. **用户名/密码不能自助注册**（`501 UNIMPLEMENTED: you can not signup just by username and password`），须由管理端/后端创建用户。
6. **匿名登录需在控制台"身份源列表"开启**：仅 `manageAppAuth(patchLoginStrategy{anonymous:true})` **不够**，直接调匿名接口仍返回
   `LOGIN_TYPE_DISABLED: 请联系开发者在身份源列表开启匿名登录`。
7. JWKS 公钥会**轮换**：按 `kid` 缓存与刷新，并保留回退（如 `@cloudbase/node-sdk` 校验）。

## 四、对规格的改动

- §9 / R-AUTH：把"通过 iss 获取 JWKS"落为**具体地址** `…/auth/v1/certs`，并注明 RS256、`aud=<envId>`、`sub`=UID、iss 双域注意事项。
- 认证实现：前端用 `@cloudbase/js-sdk` 登录拿 token；api/agent 本地按上述步骤验签（缓存 JWKS）。
- Q1（JWKS 地址与算法）**已解决**。
