# M2 沙盒持久化验证结论

- 日期：2026-10-02
- 范围：开发态工作区持久化
- 结论：**采用 AGS 原生 COS 存储挂载**——沙盒内 `/workspace/work` 直接就是 COS 目录，读写实时持久化；每游戏用实例级 `x-mounts.subPath` 隔离。
- 备选（已验证但**不再作为主方案**）：标准 E2B `pause/resume` + 平台侧打包同步。

## 一、结论依据（实测）

| 验证项 | 结果 |
|---|---|
| 沙盒内写 `/workspace/work/x` | ✅ COS `games/{game_id}/x` **立即出现** |
| 往 COS 放对象 | ✅ 沙盒 `/workspace/work` **立即可见可读** |
| 销毁沙盒 → 重建（同 `subPath`） | ✅ 数据**仍在**（真持久化） |
| 实例级 `subPath` 隔离 | ✅ 带 `subPath=g-e2e` 只看到 `games/g-e2e/**`，不越界 |
| 挂载形态 | `virtiofs`；`node_modules` 必须烘镜像、不放挂载层 |

## 二、配置模型

| 层 | 配置 |
|---|---|
| Tool 级 | 一个 COS `StorageMount`：`BucketPath=/games` → `MountPath=/workspace/work` |
| Instance 级 | 标准 E2B `metadata["x-mounts"]`：`subPath={game_id}` |

```python
sandbox = Sandbox.create(
    template="ai-game-platform-test-aio",
    timeout=3600,
    metadata={
        "game_id": game_id,
        "x-mounts": json.dumps([
            {"name": "work", "subPath": game_id,            "mountPath": "/workspace/work"},
            {"name": "work", "subPath": f"{game_id}/input", "mountPath": "/workspace/input", "readOnly": True},
        ]),
    },
)
sandbox.commands.run("ls /workspace/work", user="root")   # 访问挂载点必须 root
```

## 三、关键坑（踩出来的，必须遵守）

1. **不要传 `Endpoint`**。显式写 `cos.ap-shanghai.myqcloud.com` 会导致挂载失败、沙盒创建 `500 FailedOperation.Timeout`；**省略 Endpoint** 让 AGS 按地域自动补全即可。
2. **需要 CAM 角色**：信任主体 `sandboxtool.ags.cloud.tencent.com`，挂策略 `QcloudAccessForAgsCosReadWrite`（现成策略，PolicyId 274481109）。
   - 服务相关角色 `AGS_QCSLinkedRoleInSandboxTool` **不能**直接作为 `RoleArn` 传入（`sts:AssumeRole` 被拒）。
3. **COS 路径必须预先存在**：Tool 的 `BucketPath`、以及每个实例 `subPath` 指向的目录，都要先有对象（占位 `.keep`）才能挂载。
4. **沙盒内访问挂载点必须 `user="root"`**；默认用户无权。
5. 用 `agr`（CLI）或控制台创建带挂载的工具；`agr tool update` 不支持改 `StorageMounts`，改挂载需新建工具。

## 五、复现

```bash
# 1) 建角色（或用控制台：新建角色→腾讯云产品服务→Agent 沙箱服务(ags)）
tccli cam CreateRole --RoleName ai-game-platform-test-role \
  --PolicyDocument '{"version":"2.0","statement":[{"action":"name/sts:AssumeRole","effect":"allow","principal":{"service":["sandboxtool.ags.cloud.tencent.com"]}}]}' --region ap-shanghai
tccli cam AttachRolePolicy --AttachRoleName ai-game-platform-test-role --PolicyId 274481109 --region ap-shanghai

# 2) 建桶并放占位
#    create_bucket(ai-game-platform-test-1327210567); put_object(games/.keep, games/<game_id>/.keep)

# 3) 建带挂载的 aio 工具（不传 Endpoint）
agr --region ap-shanghai tool create --tool-name ai-game-platform-test-aio --tool-type aio \
  --network-configuration '{"NetworkMode":"PUBLIC"}' \
  --role-arn qcs::cam::uin/100037354656:roleName/ai-game-platform-test-role \
  --storage-mounts '[{"Name":"work","MountPath":"/workspace/work","ReadOnly":false,"StorageSource":{"Cos":{"BucketName":"ai-game-platform-test-1327210567","BucketPath":"/games"}}}]' \
  --wait -o json

# 4) 起沙盒写入并验证（见 §二/§一）
```

## 六、与备选方案（`pause/resume`）的对比

| 维度 | COS 挂载（采用） | `pause/resume` + 打包同步（弃用为主方案） |
|---|---|---|
| 数据位置 | 始终在 COS | 存沙盒，需显式同步到 COS |
| 同步代码 | 无 | 需自研打包/还原 |
| 每游戏隔离 | `subPath` | 每沙盒或自研目录 |
| AGS 支持 | ✅（本次验证） | ✅ 仅 `keep_memory=False` |
| 代价 | 需 CAM 角色 + COS 桶（平台一次性） | 无额外云资源 |

> 早期对标准 E2B 原语做过探测：`Volume` 404、`create_snapshot()` 内存不支持、默认 `pause()` 恢复 500——故 AGS 上持久化首选 COS 挂载。

## 七、风险 / 待办

- COS 挂载对**大量小文件**（构建产物）的读写性能待实测（`node_modules` 已用镜像规避）。
- 每游戏 COS 子路径的**预创建**与归档清理需平台流程实现（规格 Q3）。
- AGS `StorageMount` 需预先准备 CAM 角色与桶，属平台一次性基建。
