## 1. AGS 沙盒（开发态）

### 1.1 实测参数

| 项 | 值 |
|---|---|
| 区域 / 域名 | 上海 `ap-shanghai.tencentags.com` |
| 工具类型 | `aio`（All-In-One）**预置类型，无需自建镜像**；`Sandbox.create(template=…)` 可直接填 ToolId（`sdt-…`） |
| 网络模式 | **必须 `PUBLIC`**（`SANDBOX` 不通外网：无法 `npm/pip install`、无法访问数据库） |
| 预装 | Node v20、Chromium、code-server、Jupyter、Python3 |
| 默认用户 / HOME | `user` / `/home/user`；**访问 COS 挂载点须 `user="root"`** |
| 端口 | `9000` = NoVNC / VSCode / WebShell(ttyd)，`49999` = 代码执行，`49983` = 文件 / 命令 |
| SDK | E2B Python SDK（AGS 兼容）：`Sandbox.create(template, timeout, metadata)` |

### 1.2 预览：NoVNC 与直连嵌入（开发期方案）

预览 URL 格式：

```
https://{host:9000}/novnc/vnc.html?access_token=<t>&path=websockify%3Faccess_token%3D<t>&autoconnect=1&resize=scale
```

- **必须** `resize=scale` 才适配窗口；建议提供「适应窗口 / 原始比例」切换。
- **前端可直接 iframe 嵌入**（跨域）——实测：
  - AGS 响应**无** `X-Frame-Options`、**无** CSP `frame-ancestors`；
  - iframe 内 NoVNC 正常渲染 canvas，websockify（WebSocket）直连成功；
  - 截图证据：`附录/sandbox/artifacts/m1b_iframe.png`（NoVNC 里可见沙盒内 Chromium）；
  - 参考脚本：`附录/sandbox/m1b_novnc_iframe_verify.py`。
- ⚠️ **安全提示**：URL 中的 `access_token` 是沙盒**全权限凭证**（文件 / 代码执行 / CDP 均可用）。开发期直连可接受；**上线前**必须改为后端同源反代（隐藏 token + 用户鉴权），路径约定见《02》§6.3 R-PRE-4。

### 1.3 CDP（AI 操作浏览器）

- 地址：`https://{host:9000}/cdp?access_token=<t>`（也可用请求头 `X-Access-Token`）。
- 外部 Playwright `connect_over_cdp` 可用；**CDP 操作的浏览器与 NoVNC 显示的是同一个 Chromium**（"用户能操作 + 看得到 AI 操作"由此成立）。

### 1.4 坑

- 本机开代理（Clash 等）时 `*.tencentags.com` 可能被解析到 `0.0.0.0` → 连不通；需关代理或放行。
- 沙盒内首次 `curl` 轮询可能早于服务绑定端口，需容错重试。
- 沙盒内安装 Python 依赖：公网 PyPI 慢，**用腾讯云镜像** `https://mirrors.cloud.tencent.com/pypi/simple`。
- 沙盒是有生命周期的：验证时设 `timeout`，用完 `kill`。

## 2. 沙盒持久化（AGS 原生 COS 挂载）

**结论**：`/workspace/work` 直接就是 COS 目录，读写**实时持久化**；每游戏用实例级 `x-mounts.subPath` 隔离。无需自研同步 / 快照。

- 备选方案（已验证但**不采用**）：标准 E2B `pause/resume` + 平台侧打包同步到 COS。
- 说明：AGS 挂载用的 COS 与 CloudBase 的"对象存储"**是同一产品、不同桶**；本架构统一使用**独立桶**（AGS 挂载 + 版本包），不使用 CloudBase 环境托管桶。

### 2.1 配置模型

- Tool 级：`StorageMount{ Name:"work", BucketPath:"/games", MountPath:"/workspace/work" }`（**不得传 `Endpoint`**，AGS 自动补全）。
- 实例级：

```python
metadata={
    "game_id": game_id,
    "x-mounts": json.dumps([
        {"name": "work", "subPath": game_id,            "mountPath": "/workspace/work"},
        {"name": "work", "subPath": f"{game_id}/input", "mountPath": "/workspace/input", "readOnly": True},
    ]),
}
```

### 2.2 实测事实

| 验证项 | 结果 |
|---|---|
| 沙盒写 `/workspace/work/x` | COS `games/{game_id}/x` **立即出现** |
| 往 COS 放对象 | 沙盒内**立即可见可读** |
| 销毁 → 重建（同 `subPath`） | 数据**仍在**（真持久化） |
| 不同 `subPath` | 互不可见（隔离成立） |
| 挂载形态 | `virtiofs`；`node_modules` 必须烘镜像、**不放挂载层** |

### 2.3 坑（必须遵守）

1. **不要传 `Endpoint`**：显式写 `cos.ap-shanghai.myqcloud.com` 会导致挂载失败、沙盒创建 500。
2. **需要 CAM 角色**：信任主体 `sandboxtool.ags.cloud.tencent.com`，挂策略 `QcloudAccessForAgsCosReadWrite`（PolicyId 274481109）。服务相关角色 `AGS_QCSLinkedRoleInSandboxTool` **不能**直接作为 `RoleArn`。
3. **COS 路径必须预先存在**：Tool 的 `BucketPath` 与每个实例 `subPath` 目录都要先放占位对象（如 `.keep`）。
4. **沙盒内访问挂载点必须 `user="root"`**。
5. 工具创建后**不支持修改 `StorageMounts`**（需新建工具）。
6. 大量小文件（如 `node_modules`）不要放挂载层，性能差且拖慢沙盒。

## 3. 自建 PostgreSQL（VPS）

### 3.1 服务器实测

| 项 | 值 |
|---|---|
| 版本 | PostgreSQL 17.11（Debian） |
| 地址 | 公网 `152.32.215.89:10050`（Docker 端口映射；容器内 172.19.0.2:5432） |
| 管理员 | `root`：**SUPERUSER + CREATEDB + CREATEROLE + LOGIN**（凭据见 `env.md`） |
| SSL | ❌ `ssl=off`（连接为明文；**上线前必须启用**） |
| 实例性质 | **共享实例**（同实例还有用户其它业务库）；只动平台自己的库 / role |

### 3.2 开通（幂等）

```sql
-- 一次性：平台元数据库
CREATE DATABASE aigame_platform;
REVOKE CONNECT ON DATABASE aigame_platform FROM PUBLIC;
CREATE ROLE platform_rw LOGIN PASSWORD '<platform_pwd>';
GRANT CONNECT ON DATABASE aigame_platform TO platform_rw;
-- （连入 aigame_platform 后建平台元数据表并授权）

-- 每游戏（sid = game_id 去横线）
CREATE DATABASE game_{sid};
REVOKE CONNECT ON DATABASE game_{sid} FROM PUBLIC;      -- 关键！
CREATE ROLE game_{sid}_rw LOGIN PASSWORD '<pwd>';       -- pwd = base64url(HMAC-SHA256(master_secret, game_id))
GRANT CONNECT ON DATABASE game_{sid} TO game_{sid}_rw;
-- （连入 game_{sid} 库）
GRANT USAGE, CREATE ON SCHEMA public TO game_{sid}_rw;
```

- `CREATE DATABASE` 不能在事务里执行；实测耗时 ~100ms。
- 开通**必须幂等**：存在则跳过，**不重建、不改密码**（否则滚动更新期间旧实例会 `password authentication failed`，实测踩过）。
- 连接串（派生，不落库）：

```
postgresql://game_{sid}_rw:<pwd>@<PG_HOST>:<PG_PORT>/game_{sid}?sslmode=disable
（SSL 启用后必须改为 sslmode=require）
```

### 3.3 隔离实测（关键坑）

| 场景 | 结果 |
|---|---|
| 默认（建库后未收权）：role_A 连 **game_B 库** | **成功（越库！）** |
| `REVOKE CONNECT … FROM PUBLIC` 后：role_A 连 game_B | 被拒 ✅ |
| role_A 连自己的库并读写 | 成功 ✅ |

> PostgreSQL 建库默认给 `PUBLIC` 授予 `CONNECT`，**不收权则任意 role 可连任意库**。游戏库与平台库**都必须** `REVOKE CONNECT … FROM PUBLIC`。
> （测试中曾误改共享 `postgres` 库 ACL，已恢复原状；今后勿动共享库的 ACL。）

### 3.4 沙盒 / 托管直连实测

| 场景 | 结果 |
|---|---|
| AGS 沙盒 → VPS PG TCP | ✅ 可达（沙盒 PUBLIC 网络） |
| 沙盒内用游戏 role 连接并建表写入 | ✅（整段探针 0.6s） |
| `sslmode=require` | ❌ `server does not support SSL` |
| CloudRun 服务（发布态）经注入 `DATABASE_URL` 连接 | ✅ 见 §4 |

## 4. 发布：CloudBase 云托管（CloudRun）

### 4.1 部署 API 链路（后端代码直接调，无需 MCP / 控制台）

流程与 `@cloudbase/manager-node` 的 `cloudrun.deploy()` 等价：

| # | API（产品） | 作用 |
|---|---|---|
| 1 | `tcb:DescribeCloudBaseBuildService(EnvId, ServiceName)` | 返回 `UploadUrl` / `UploadHeaders` / `PackageName` / `PackageVersion` |
| 2 | HTTP `PUT UploadUrl` | 上传源码 zip |
| 3 | `tcbr:CreateCloudRunServer` / `UpdateCloudRunServer` | `DeployInfo={DeployType:"package", PackageName, PackageVersion, ReleaseType:"FULL"}` + `Items`（见下） |
| 4 | `tcbr:DescribeCloudRunServerDetail` | `BaseInfo.DefaultDomainName` / `BaseInfo.Status`；`ServerConfig.EnvParams` 回显；`OnlineVersionInfos` 看镜像 |
| 5 | `tcbr:DescribeCloudRunDeployRecord` | 部署记录（`Status` / `FlowRatio` / `BuildId`） |

`Items`（容器型 + Dockerfile，与 manager-node 的 `parseObjectToDiffConfigItem` 一致）：

```python
[
    {"Key": "AccessTypes", "ArrayValue": ["PUBLIC"]},
    {"Key": "MinNum", "IntValue": 0},
    {"Key": "EnvParam", "Value": json.dumps({"DATABASE_URL": "...", "PORT": "3000", "NODE_ENV": "production"})},
    {"Key": "InitialDelaySeconds", "IntValue": 0},
    {"Key": "HasDockerfile", "BoolValue": True},
    {"Key": "Port", "IntValue": 3000},
    {"Key": "Dockerfile", "Value": "Dockerfile"},
]
```

- 后端依赖：Python `tencentcloud-sdk-python-tcb` + `tencentcloud-sdk-python-tcbr`（Node 侧可用 `@cloudbase/manager-node`）。
- 参考实现：`附录/cloudbase/api_deploy_verify.py`；探针工程：`附录/cloudbase/probe-app/`。

### 4.2 实测证据（2026-10-08）

- 部署记录 `status=normal`、`flow=100`；默认域名形如 `https://<svc>-<rand>.sh.run.tcloudbase.com`。
- 服务经注入的 `DATABASE_URL` 直连 VPS PG：
  - `GET /` → 200；
  - `GET /db` → 200，返回 `current_user=game_apideploy_probe_rw`、`PostgreSQL 17.11`。
  - **结论：云托管 → VPS PG 公网直连成立，无需 VPC。**
- 镜像地址形如 `ccr.ccs.tencentyun.com/tcb-<uin>-<rand>/ca-…:<version>`。

### 4.3 WebSocket

- 容器型云托管**支持 WebSocket**（socket.io `transport=websocket` 实测收发正常）。
- **60s 空闲断开**：WS 建立后 60s 无数据会被网关断开 → **必须心跳**（建议每 10s）。
- HTTP 请求超时 60s。

### 4.4 坑

1. **`ResourceInUse`**：上一次部署任务未结束时再次提交 → `当前已有部署发布任务运行中,请结束后再执行`。必须**轮询 / 重试**（如 30s × N）。
2. `DescribeCloudRunServerDetail` 数据在 `BaseInfo` / `ServerConfig` / `OnlineVersionInfos` 下，**没有**顶层 `DefaultDomainName`（易踩）。
3. **源码构建偶发瞬时失败**（推镜像到 CCR 报 `broken pipe`）→ **重试即成功**。
4. **端口必须与服务监听一致**（容器型需显式配置 `Port`）。
5. `MinNum=0` 可缩容到 0（有冷启动）；默认为 `OperationMode: alwaysScale`。
6. **滚动更新期间旧实例仍持旧配置**——改库密码 / 连接串会造成短暂 5xx。
7. 默认域名仅建议测试；生产建议绑自定义域名。

## 5. CloudBase 认证与 PG 调研存档（**为什么不用**）

> 以下为调研结论，仅供理解决策背景；新项目**不采用**这些机制。

### 5.1 认证

- CloudBase 的 JWT 也是 **RS256 + 公开 JWKS**，可本地验签——**模式本身没问题**（自建认证沿用该模式）。
- 但 CloudBase 环境有**两套签名域**：网关（`api.tcloudbasegateway.com`，REST 数据面）与 `tcb-api`（OIDC / 自定义登录），互不认签。
- 自定义登录 token：不被网关 REST 接受（`ACCESS_TOKEN_KID_INVALID`）、且没有 `role` claim；网关匿名登录可用但身份完全由 CloudBase 控制。
- → 认证不可控、属黑盒，弃用，改自建。

### 5.2 数据库

| 能力 | 结果 |
|---|---|
| 沙盒 / 云托管直连 CloudBase PG（内网地址） | ❌ 不可达（不在同一网络） |
| `CREATE ROLE`（云 API `ExecutePGSql`） | ❌ `permission denied to create role (42501)`（管理员子账号直调亦然） |
| PostgREST 暴露范围 | 仅 `public` schema |
| PostgREST + RLS（`auth.uid()`） | 技术上可行（实测隔离通过） |
| `service_role` | 可绕过 RLS（只能给平台后端） |

- → 无法实现"每游戏独立库 / role + 直连"，故改**自建 PG**（A1）。

## 6. 坑速查表（跨模块）

| # | 坑 | 规避 |
|---|---|---|
| 1 | AGS 挂载传了 `Endpoint` | **不传**，由 AGS 补全 |
| 2 | COS 路径不存在导致挂载失败 | 挂载前先建占位对象 |
| 3 | 沙盒访问挂载点报权限 | 用 `user="root"` |
| 4 | 沙盒网络 `SANDBOX` 无外网 | 用 `PUBLIC` |
| 5 | NoVNC 画面不适配 | 加 `resize=scale` |
| 6 | 沙盒 `node_modules` 拖慢挂载 | 依赖烘镜像 |
| 7 | CloudRun 源码构建偶发 `broken pipe` | 重试 |
| 8 | CloudRun WS 60s 空闲断开 | 每 10s 心跳 |
| 9 | CloudRun 端口不一致 | 容器端口 = 服务监听端口 |
| 10 | CloudRun 部署中再提交 → `ResourceInUse` | 轮询等待 / 重试 |
| 11 | PG 建库默认 `PUBLIC` 有 CONNECT → 越库 | `REVOKE CONNECT … FROM PUBLIC` |
| 12 | PG 未启用 SSL（明文） | 上线前启用（自签 + `sslmode=require`） |
| 13 | 重建游戏库 / 换密码 → 滚动窗口 5xx | 开通幂等：不重建、不改密码 |
| 14 | `DescribeCloudRunServerDetail` 找错层级 | 用 `BaseInfo.DefaultDomainName` |
| 15 | 沙盒内装依赖慢 | 腾讯云 pip 镜像 / 依赖烘镜像 |
