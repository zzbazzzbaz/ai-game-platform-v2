## 2. 开发阶段任务（建议顺序）

### 第 1 步：搭建骨架（apps/）

- `apps/api`（FastAPI）：认证、游戏 / 会话 CRUD、沙盒编排、PG 开通、预览、发布、平台内部接口。
- `apps/agent`（LangGraph Server + deepagents）：对话编排与自定义工具。
- `apps/web`（React + Vite SPA）：登录、对话、预览、版本。
- `packages/game-template`：游戏工程模板（Node 后端 + Phaser 前端）。
- `packages/contracts`：共享契约（api / agent / web）。
- 目录结构与接口清单见《02-技术架构规格》§10 / §11 / §12。

### 第 2 步：M5 生成闭环（最高优先）

**目标 / 验收**：多轮对话生成一个带 Node 后端的游戏；沙盒内跑起来；预览可玩；会话结束后工作区保持。

- 关键链路：web → api → LangGraph(agent) → 工具 → AGS 沙盒（写文件 / 运行 `npm run dev` / CDP 自检 / 截图）。
- Agent 工具（规格 §6.4）：
  - `provision_database()`：开通本游戏库并注入 `DATABASE_URL`；
  - `restart_server()`：重启游戏服务并返回日志；
  - `screenshot()`：CDP 截图供自检（限次）；
  - `publish_game(name)`：发布（第 3 步接入）。
- 依赖的已验证事实：《03》§1（沙盒）、§2（挂载）、§3（PG）。
- 待调参 / 待决策：Agent 单轮时长阈值（Q6）、自检轮数上限（R-AGT-3）、生成区边界（R-AGT-1）。

### 第 3 步：M6 收尾

- 把发布工具接进 Agent：`publish_game` → api → 《03》§4 的部署链路（注入 `DATABASE_URL`）。
- 端到端验收：生成 → 发布 → 公网链接可打开、可玩（含 WS 心跳 10s）。
- 发布成功后写 `game_versions`（M7 基础），更新 `games.public_url`。

### 第 4 步：M7 版本

- 版本列表接口与页面；当前在线版本由"`status='deployed'` 且 `seq` 最大"派生；`public_url` 跨版本稳定。

### 并行：平台自身

- 认证实现（RS256 + 平台 JWKS；access 2h / refresh 30d）。
- 平台元数据表与迁移（`aigame_platform` 库）：`users` / `games` / `game_threads` / `game_versions`。
- **上线前必做**：NoVNC 同源反代（R-PRE-1/2/4）、PG 启用 SSL（改 `sslmode=require`）、密钥轮换。
- 沙盒体验优化：镜像预装依赖（`node_modules` 烘镜像）以加速冷启动。

## 3. 开放问题（沿用规格 §14）

| 编号 | 问题 | 待办 |

## 5. 交接给开发 agent 的注意事项

1. 动手前先通读《02》（规格）与《03》（坑）；架构上的疑问以《02》为准。
2. 沙盒 / PG / 云托管的操作细节，直接照《03》执行，避免重复踩坑。
3. 任何"想当然"的网络假设都要先验证（例如：沙盒是否可达某地址、云托管能否连外网 DB——已有结论在《03》）。
4. 生成闭环（M5）**尚未验证**，是本期最大的不确定性：优先打样，尽早暴露问题。
5. 安全相关的"上线前必做项"不要遗漏（Q1 / Q8 / R-PRE-1/2/4）。
