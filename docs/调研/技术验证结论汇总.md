> 用途：把 `test/M1 ~ M6` 五份验证结论中**仍然适用于当前架构**的部分提炼成一份速查。
> 原始文档保留在 `test/`，作为完整证据与调研存档；本文只保留"现在还要用"的结论与坑。

## 0. 当前架构（v0.2 / A1）速览

| 组件 | 归属 |
|---|---|
| `apps/api`、`apps/agent`、平台前端 | **自建 VPS**（Docker + 反代 / Nginx） |
| 平台数据库（元数据 + 每游戏 schema/role） | **自建 PostgreSQL（VPS）** |
| 身份认证 | **自建**（平台签发/校验 JWT） |
| 发布出去的游戏服务 | **CloudBase 云托管（CloudRun）** |
| 对象存储（工作区/素材/版本包） | **腾讯云 COS 独立桶**（与 AGS 挂载同一个桶） |
| 开发沙盒 | 腾讯云 **AGS** |

对应规格：`docs/spec/技术架构规格.md`（Draft v0.2）。

## 1. 沙盒链路（来自 M1，仍完全适用）

**结论**：AGS 沙盒可承载"游戏服务 + 浏览器 + Agent 操作"，且**用户看到的画面与 AI 操作的是同一个 Chromium**。

要点：

| 项 | 值 / 结论 |
|---|---|
| 区域 / 域 | 上海 `ap-shanghai.tencentags.com` |
| 工具类型 | `aio`（All-In-One）**预置类型，无需自建镜像**；`template` 可填 ToolId |
| 网络模式 | **必须 `PUBLIC`**（`SANDBOX` 不通外网，无法 `npm/pip install`、无法访问数据库/API） |
| 预装 | Node v20、Chromium、code-server、Jupyter |
| 端口 | `9000`=NoVNC/VSCode/WebShell、`49999`=代码执行、`49983`=文件/命令 |
| 预览 | `https://{host:9000}/novnc/vnc.html?...&resize=scale`（**必须 `resize=scale`** 才适配窗口） |
| CDP | `https://{host:9000}/cdp?access_token=<t>`；外部 CDP 与 NoVNC 是**同一浏览器** |

**坑**：
- 本机开代理（Clash 等）时 `*.tencentags.com` 可能被解析到 `0.0.0.0`，需关代理/放行，否则连不上。
- 沙盒内首次 `curl` 轮询可能早于服务绑定端口，需容错重试。
- **尚未验证**：NoVNC 经平台后端**同源反代**（隐藏 token + 支持 WebSocket）——待 api 就绪后补验。

## 2. 沙盒持久化 / COS 挂载（来自 M2，仍完全适用）

**结论**：采用 **AGS 原生 COS 存储挂载**——沙盒 `/workspace/work` 直接就是 COS 目录，读写**实时持久化**；每游戏用实例级 `x-mounts.subPath` 隔离。

| 验证项 | 结果 |
|---|---|
| 沙盒写 `/workspace/work/x` | COS `games/{game_id}/x` **立即出现** |
| 往 COS 放对象 | 沙盒 `/workspace/work` **立即可见可读** |
| 销毁 → 重建（同 `subPath`） | 数据**仍在**（真持久化） |
| 实例级 `subPath` 隔离 | 只见 `games/{subPath}/**`，不越界 |

**配置模型**：
- Tool 级：`StorageMount{Name:"work", BucketPath:"/games", MountPath:"/workspace/work"}`
- Instance 级：`metadata["x-mounts"] = [{name:"work", subPath:"{game_id}", mountPath:"/workspace/work"}, {name:"work", subPath:"{game_id}/input", mountPath:"/workspace/input", readOnly:true}]`

**关键坑（必须遵守）**：
1. **不要传 `Endpoint`**（显式写 `cos.ap-shanghai.myqcloud.com` → 挂载失败、沙盒创建 `500`）；省略由 AGS 自动补全。
2. **需要 CAM 角色**：信任主体 `sandboxtool.ags.cloud.tencent.com`，策略 `QcloudAccessForAgsCosReadWrite`（现成策略，PolicyId `274481109`）。服务相关角色 `AGS_QCSLinkedRoleInSandboxTool` **不能**直接作为 `RoleArn`。
3. **COS 路径必须预先存在**：Tool 的 `BucketPath`、每个实例 `subPath` 目录都要先放占位对象（`.keep`）。
4. **沙盒内访问挂载点必须 `user="root"`**。
5. `agr tool update` **不支持改 `StorageMounts`**，改挂载要新建工具。
6. 挂载为 `virtiofs`；`node_modules` 等依赖**必须烘入镜像**、不放挂载层。

**测试资源**（当前架构继续用同一独立桶）：CAM 角色 `ai-game-platform-test-role`、COS 桶 `ai-game-platform-test-1327210567`（基准路径 `/games`）、沙盒工具 `ai-game-platform-test-aio`（`sdt-20q9wrvq`，aio/PUBLIC）。密钥见 `docs/chat/10.2/env.md`（gitignored）。

**说明**：AGS 挂载用的 COS 与 CloudBase 的"对象存储"**是同一产品、不同桶**。本架构统一用**独立桶**（AGS 工作区 + 版本包），**不使用** CloudBase 环境托管桶。

## 3. 游戏发布 / CloudRun（来自 M6，仍适用）

**结论**：容器型云托管支持 WebSocket；单服务同源（静态前端 + API + WS）可行；环境变量注入、默认域名、端口配置均验证通过。

| 验证 | 结果 |
|---|---|
| 部署（源码构建，容器型） | 成功（版本 normal，流量 100%） |
| HTTP | `GET /` → 200 |
| 环境变量注入 | 生效（服务内可读到 EnvParams） |
| **WebSocket** | socket.io `transport=websocket` 连接成功、收发正常 |
| 默认域名 | `https://<svc>-<random>.sh.run.tcloudbase.com`（另有 `*.ap-shanghai.run.wxcloudrun.com`） |

**关键坑**：
1. **源码构建可能瞬时失败**（推送镜像到 CCR 时 `broken pipe`）→ **直接重试即成功**。
2. **端口必须与服务监听一致**（容器型需显式配置端口）。
3. **WebSocket 有 60s 空闲断开**：WS 建立后 60s 无数据会被网关断开 → **必须心跳**（建议每 10s）。
4. 默认域名仅建议测试；生产建议绑自定义域名。
5. `MinNum=0` 可缩容到 0 省钱（有冷启动）。

**与当前架构的差异**：M6 验证时用 PostgREST 访问 CloudBase 数据；**现在改为**发布时注入 **`DATABASE_URL`**（指向自建 PG 的该游戏 DSN，公网 + SSL），游戏服务 PG 协议直连。

## 4. 认证：可复用的模式（来自 M3）

**当前架构自建认证，CloudBase 身份认证已不使用**；但 M3 验证的**模式**直接复用：

- 令牌用 **RS256 非对称签名 + 公开 JWKS**，验证方**本地离线验签**、按 `kid` 缓存并刷新。
- 访问令牌为**标准 JWT**，关键 claim：`iss` / `aud` / `sub` / `exp`；验证顺序：取 JWKS → 验签 → 校验 `iss`/`aud`/`exp` → 取 `sub`。
- 每个服务**各自独立验签**，不引入"代验"中转。

> 已废弃（勿照搬）：CloudBase 的 JWKS 地址（`…/auth/v1/certs`）、Publishable Key、匿名/自定义登录等专属机制。M3 文档作调研存档。

## 5. 数据库 / 网络：决策依据与教训（来自 M4）

**这些结论直接决定了当前架构"自建 PG"**，也定义了沙盒/游戏的连接方式：

| 实测 | 结论 |
|---|---|
| AGS 沙盒 → CloudBase PG 内网地址 | **不可达**（两者不在同一网络） |
| CloudBase PG 建 `CREATE ROLE` | **被拒**（`cloudbase_postgres` 无权限，42501） |
| CloudBase PG 形态 | 托管**共享**实例，PostgREST + JWT + RLS，**只暴露 `public`** |
| 自建 PG（VPS） | ✅ 可 `CREATE ROLE`；✅ 有公网地址 + SSL → **沙盒/云托管可直连** |

**对当前架构的用法**：
- 每游戏独立 schema + 专属 role + 连接串（PostgreSQL 协议直连，`sslmode=require`）；账号密码由 `HMAC(master_secret, game_id)` 派生，不落库。
- 平台后端/Agent 与 PG **同机/同内网**，无需把 PG 暴露给平台自身；只有**沙盒（开发态）**与**游戏服务（发布态）**经公网连 PG。
- 安全：强制 SSL + 强密码 + role 最小权限（沙盒/云托管出口 IP 不固定，难做白名单）。

> 已废弃（勿照搬）：PostgREST + RLS + `auth.uid()`、CloudBase 自定义登录（两套签名域、开关不稳定，属黑盒）。M4 文档作调研存档。

## 6. 关键坑速查表（跨模块）

| # | 坑 | 规避 |
|---|---|---|
| 1 | AGS 挂载传了 `Endpoint` | **不传**，由 AGS 补全 |
| 2 | COS 路径不存在导致挂载失败 | 挂载前先建占位对象 |
| 3 | 沙盒访问挂载点报权限 | 用 `user="root"` |
| 4 | 沙盒网络 `SANDBOX` 无外网 | 用 `PUBLIC` |
| 5 | NoVNC 画面不适配 | 加 `resize=scale` |
| 6 | 沙盒 `node_modules` 拖慢挂载 | 依赖烘镜像 |
| 7 | CloudRun 源码构建偶发 `broken pipe` | 重试 |
| 8 | CloudRun WS 60s 空闲断开 | 每 10s 心跳 |
| 9 | CloudRun 端口不一致 | 容器端口 = 服务监听端口 |
| 10 | 自建 PG 暴露公网 | 强制 SSL + 强密码 + role 最小权限 |
